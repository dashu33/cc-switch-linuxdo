# Claude 模型映射批量设置

> 维护目录：\`自用特性/Claude模型映射批量设置/\`

> 文档状态：最后同步 2026-10-15 · 新增「同步拉取结果」按角色自动落位

## 目标

让 Claude / Claude Desktop 供应商**编辑弹窗**里「高级选项 → 模型映射」这一块，和 Codex 弹窗的模型映射区能力对齐：

1. **拉取模型**（`获取模型列表`）的结果只属于本次请求，换凭证即作废
2. 拉取成功后多一个**「同步拉取结果」**按钮，把 `/models` 结果按角色名自动落到五个模型角色

改动前 Claude 侧只有「一键设置」（把同一个模型名塞给全部角色），且拉取结果在切换 Base URL / Key 后仍会残留。

## 用户行为

### 拉取模型（`获取模型列表`）

- 点击后请求 `{Base URL}/models`，成功/失败沿用原有 toast 与错误分类
- **请求身份变化即作废**：Base URL、`完整地址` 开关、API Key、自定义 User-Agent 任一变化时
  - 递增请求序号，作废在途响应（旧响应返回后直接丢弃）
  - 清空已拉取列表，避免换号后残留旧 Key 能看到的模型
- 与 Codex 侧行为一致（见 [../Codex供应商快速调整/](../Codex供应商快速调整/)）

### 同步拉取结果

按钮仅在**本次拉取成功且结果非空**时出现，位于「模型映射」标题行的「一键设置」左侧。

点击后按以下规则写入模型角色：

| 角色 | 取值规则 |
|------|----------|
| Sonnet | `/models` 结果中第一个模型 id 含 `sonnet` 的 |
| Opus | 第一个含 `opus` 的 |
| Fable | 第一个含 `fable` 的 |
| Haiku | 第一个含 `haiku` 的 |
| Subagent | 沿用当前「默认兜底模型」（`ANTHROPIC_MODEL`） |

- 大小写不敏感的子串匹配
- **未命中或兜底为空的角色保持原值**，不覆盖用户已填内容
- 命中数 > 0 时 toast 汇报「已按角色填入 N 个模型」；全部未命中时提示手动选择
- 写入走 `handleRoleModelChange`，因此显示名称（`*_MODEL_NAME`）与 1M 标记规则与手工填写完全一致

「一键设置」保留原有语义（把同一个模型名应用到所有角色），不改变。

## 关键决策

1. **为什么用关键词匹配而不是顺序填充**：`/models` 的返回顺序由上游决定，与角色语义无关；按顺序填会出现 Opus 角色里是 Haiku 模型这类错配。
2. **Subagent 复用兜底模型**：上游模型列表里没有与 `subagent` 对应的品牌模型，该角色本来的定位就是「落到兜底模型」。
3. **只在拉取成功后出现**：没有本次结果就没有可落位的数据，常显按钮只会误导。
4. **不修改「一键设置」**：两者语义不同（同一模型 vs 按角色分发），保留旧按钮避免破坏既有习惯。
5. **与 Claude Desktop 共用**：`ClaudeFormFields.tsx` 同时服务 `claude` 与 `claude-desktop`，行为一致。

## 非目标

- 不改动卡片上的快速调整控件（见 [../Codex供应商快速调整/](../Codex供应商快速调整/)）
- 不改动 Codex / Grok Build 等其它应用的模型映射区
- 不做模型 → 角色的自动下游探测（如按 context window 猜测），只按名字匹配

## 兼容与迁移

- 纯前端交互增强，无数据结构变化，无持久化字段新增
- 已有供应商无需迁移；已填写的模型角色不会被自动改动

## 验收标准

- [ ] 拉取成功后出现「同步拉取结果」按钮；拉取失败或结果为空时不出现
- [ ] 点击后 Sonnet / Opus / Fable / Haiku 分别落入含对应关键词的模型
- [ ] 结果里没有某角色关键词时，该角色保持原值
- [ ] Subagent 落入当前兜底模型；兜底为空时保持原值
- [ ] 切换 API Key 或 Base URL 后，已拉取列表被清空，按钮消失
- [ ] 在途请求返回时若凭证已变更，结果不写入列表
